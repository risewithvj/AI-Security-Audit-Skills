# File upload and download

HR, payroll, KYC and document-management apps live on file handling. Load this when the app accepts or serves files.

## Upload

| Check | Confirmed when |
|---|---|
| **Type validation** happens on the server from content (magic bytes) or a strict allowlist, not only the client or the `Content-Type` header | A user can store an `.html`, `.svg`, `.php`, `.jsp`, `.aspx` or other active file that is later served from the app's own origin, or executed |
| **Storage location** is outside the web root, or the storage serves files with `Content-Disposition: attachment` and a safe `Content-Type` | Uploaded files are served inline from the main origin (stored XSS through SVG/HTML) or from an executable directory |
| **File name** is generated by the server, not taken from the user | The user-supplied name reaches a filesystem path (path traversal, overwrite: `../../`, absolute paths, Windows `..\\`, alternate data streams, null bytes in old runtimes) |
| **Archive extraction** checks every entry path | Zip/tar entries with `../` escape the target folder (zip slip), or symlink entries |
| **Size and count limits** exist on the server | Unbounded uploads fill disk or memory on a shared server (see [resource-exhaustion.md](resource-exhaustion.md)) |
| **Parsers** for images, PDFs, Office files, XML, CSV run safely | XML parsers with external entities enabled (XXE); ImageMagick/Ghostscript on untrusted files without a safe policy; CSV exports that start cells with `=`, `+`, `-`, `@` (formula injection) when opened by staff |
| **Malware scanning** | Only report missing scanning as a hardening note unless files are shared with other users and the app claims to scan |

## Download and document access

- Every download route checks that the caller may read **that** document (see [api-authorization.md](api-authorization.md) BOLA). Document IDs from the client are attacker-controlled.
- Signed or pre-signed URLs: short expiry, bound to the object, not reusable across users, not logged or placed in referrers.
- Direct object storage access: bucket and object ACLs are private; public URLs are not guessable sequences.
- Path parameters joined to a base directory are normalised and checked to stay inside it (`path.resolve` then `startsWith(base)`), including on Windows path rules.
- Generated documents (payslips, offer letters, Form 16) are stored per user and per tenant, not in a shared folder with predictable names.

## Typical smallest fixes

- Server-generated random names; store the original name only as metadata.
- Allowlist of extensions and verified content type; serve as attachment from a separate domain or with `Content-Security-Policy: sandbox`.
- One ownership-checked download handler for all documents; delete direct links.
- Short-lived, user-bound signed URLs.
- Regression test: upload `x.svg` with a script, fetch it, assert it is not served inline as `image/svg+xml` from the app origin; user A downloads user B's document and gets 403/404.
