OWASP Juice Shop — v1.5.1 Benchmark

Fresh AISA CLI v1.5.1 run vs the same web-AI reports, scored against a mechanically-selected Core 30 / Full 60 answer key. Same rules for every tool. Measured 2026-11-11.

Core 30 frozen before scoring. The 30 headline challenges were picked mechanically from Juice Shop's own category/tags (OWASP-mapped classes only; puzzles/OSINT/Web3 excluded), then the first 30 by difficulty. Rule + list: tests/benchmark/core30.md. Per-challenge file/class answer key: juice-shop.labels.json.
Two scores, same rules for everyone. Strict counts only the distinct challenges a tool identified by the right file AND the right bug class. Coverage credits a found vulnerability with its sibling challenges in the same file (e.g. one login SQLi finding credits all login challenges). Coverage ≥ Strict for every tool.
Read honestly: this is not a clean model-vs-model comparison. Claude.ai was partial — about 40 routes and the client-side phase were not reached; it used 31% of the session's usage. Codex used the softer defensive prompt. Gemini Pro refused the task (no score). The CLI figure is a fresh v1.5.1 run (not a re-score). Zero false positives across all tools on Juice Shop (a deliberately vulnerable app, so this measures precision only on known-vulnerable code).

What the numbers say

On the frozen Core 30 the CLI engine (25) found more than twice any single web AI (7–11) and more than all three combined (14). On exact Full-60 matches the CLI (46) beats the web union (29). On the looser coverage metric the field is close (CLI 53 vs 45–48), so the engine's real advantage is precision and completeness, not reaching bugs the web AIs cannot. The CLI's 5 Core misses (chatbot/LLM in routes/chat.ts, the admin-section guard, reflected-XSS in track-result, and the deleted-user ghost login) are honest coverage gaps in this run.
